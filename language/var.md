## 1. 什么是变量 🟡

变量 = **一块有名字的内存**，用来存放程序运行中会变化的数据。

```cpp
int a = 10;
```

这一句做了三件事：申请 4 字节内存 → 起名叫 `a` → 把 `10` 写进去。

⚠️ `=` 是**赋值**（把右边的值写进左边），不是数学上的"等于"。判断相等要用 `==`。

```cpp
a = a + 1;   // 合法：把「a 当前值 +1」写回 a
```

## 2. 变量的分类（按存储位置）🟡

| 类别 | 说明 | 例子 | 存哪 | 默认值 | CSP |
|---|---|---|---|---|---|
| **局部变量** | 函数或 `{}` 内 | `int x;` | 栈 | **随机垃圾值** | 🔴 |
| **全局变量** | 所有函数外面 | `int g;` | 静态区 | **自动 0** | 🔴 |
| **静态变量** | `static` 修饰 | `static int s;` | 静态区 | **自动 0** | ⚪ |
| **成员变量** | 结构体/类内部 | `struct E { int w; };` | 跟随宿主对象 | 跟随宿主 | 🟡（S 组） |
| **常量** | `const` / `constexpr` | `const int c = 1;` | 静态区/编译期 | 必须初始化 | 🟡 |
| **寄存器变量** | `register`（**已废弃**） | `register int i;` | 由编译器决定 | 随机 | ⚪ |

**两条主线**（下面第 6 节会展开）：

- **存哪**决定了能开多大：栈只有 1~8 MB，静态区很大 → **大数组必须开全局**
- **默认值**决定了要不要手动清零：栈上是垃圾值，静态区自动 0 → **局部变量必须初始化**

> 🟡 第一轮"下列变量存储在栈上的是"这类概念题就考这张表，**记住前三行即可**。

### 静态变量 `static` ⚪

`static` 局部变量：**只初始化一次，函数退出后值还在**（本质是"放在静态区、但只有函数内能访问"的变量）。

```cpp
void f() {
    static int cnt = 0;   // 只在第一次调用时执行这句
    cnt++;
    cout << cnt << " ";
}

int main() { f(); f(); f(); }    // 输出：1 2 3
```

实测输出确认为 `1 2 3`。去掉 `static` 则每次都重新变回 0，输出 `1 1 1`。

> ⚪ **第二轮基本不用**——要跨调用保存状态，直接开全局变量更直观，也更好调试。
> 🟡 但第一轮"阅读程序写输出"**偶尔会拿它出题**，能看懂上面这个例子就够了。

### 成员变量（结构体）🟡（CSP-S 常用）

```cpp
struct Edge {
    int u, v, w;      // u、v、w 就是成员变量
};

Edge e = {1, 2, 5};
cout << e.w;          // 用 . 访问，输出 5
```

⚠️ **成员变量的默认值跟着宿主走**，实测：

```cpp
Edge g_e;             // 全局 → 成员全是 0
Edge l_e;             // 局部 → 成员是垃圾值（实测 32758、48）
```

> 🟡 **CSP-S 图论题的标配**：`vector<Edge> g[N]` 存邻接表、按边权排序跑 Kruskal。
> 详见 [README.md 第 9 节](./README.md)。**CSP-J 用不到，可跳过。**

### 寄存器变量 `register` ⚪（已废弃，只需认识）

老代码里会看到这种写法，本意是"建议编译器把这个变量放进 CPU 寄存器加速"：

```cpp
register int i;
for (register int j = 0; j < n; j++) ...
```

**现在不要再写了**，原因有三：

1. **C++17 起已废弃**。实测用 `-std=c++17` 编译会报警告：
   `warning: ISO C++17 does not allow 'register' storage class specifier`
   （`-std=c++11` / `c++14` 下还能静默通过，但也只是兼容旧代码）
2. **没有任何效果**。现代编译器的寄存器分配比人聪明得多，这个关键字早就被忽略了
3. 早年 NOIP 选手爱写 `register int i` 卡常，**那是十几年前的经验，已经完全过时**

> ⚪ **只需要"看到老代码时知道它是什么"**，自己一个字都不用写。

## 3. 定义与初始化 🔴

```
类型名 变量名;              // 只定义，不给初值
类型名 变量名 = 初值;        // 定义并初始化（考场上一律用这个）
```

```cpp
int a;             // 未初始化 —— 值是垃圾，危险
int b = 5;         // 初始化为 5
int c = 5, d = 6;  // 一行定义多个
int e, f = 7;      // ⚠️ 只有 f 被初始化，e 仍是垃圾值
```

### ⚠️ 高频丢分点：局部变量不初始化是**随机值** 🔴🔴

```cpp
int main() {
    int a, b, c;
    cout << a << " " << b << " " << c << endl;
}
```

实测输出（每次运行可能都不一样）：

```
0 16 583
```

**不是 0！** 很多同学以为默认是 0，于是写出这种代码：

```cpp
int sum;                       // ❌ 没初始化
for (int i = 1; i <= n; i++)
    sum += a[i];               // 从垃圾值开始累加，答案全错
```

正确写法：

```cpp
int sum = 0;                   // ✅ 累加器必须清零
```

**记住这四个初值**：

| 用途 | 初值 |
|---|---|
| 累加器 | `sum = 0` |
| 累乘器 | `product = 1` |
| 求最大值 | `mx = -INF`（或 `-1`，若保证非负） |
| 求最小值 | `mn = INF` |

> 🔴 **这是第二轮最容易 0 分的错误之一**：本地测样例可能碰巧对（垃圾值恰好是 0），
> 交上去换个环境就全错。务必养成"定义即初始化"的肌肉记忆。

## 4. 命名规则 🟡

**硬性规定**（违反直接编译错误）：

- 只能用**字母、数字、下划线**，且**不能以数字开头**
- **区分大小写**：`a` 和 `A` 是两个不同的变量
- 不能用**关键字**：`int`、`for`、`return` 等

```cpp
int  n;          // ✅
int  max_value;  // ✅
int  _tmp;       // ✅
int  2sum;       // ❌ 数字开头
int  my-var;     // ❌ 不能有减号
int  int;        // ❌ 关键字
```

> 🟡 **第一轮必考题型**："下列哪个是合法的标识符？" 上面三条规则记牢就是白送的分。

### ⚠️ 避开标准库已有的名字 🔴

`max`、`min`、`count`、`next`、`hash`、`y1` 等。写了 `using namespace std;` 后重名会**编译错误**。

> 🔴 `y1` 是最经典的坑（它在数学库里是贝塞尔函数）。做几何题习惯性写
> `int x1, y1, x2, y2;` 结果编译失败，考场上很容易慌。**改成 `ya`、`yy1` 或 `Y1` 即可。**

## 5. 作用域 —— 变量能在哪用 🟡

变量**只在它所属的那对 `{ }` 里有效**，出了大括号就不存在了。

```cpp
int g = 10;               // ① 全局：整个文件都能用

int main() {
    int a = 20;           // ② 局部（函数）：只在 main 内有效

    for (int i = 0; i < 5; i++) {
        int t = i * 2;    // ③ 块：只在这个 for 的花括号内有效
    }
    // cout << i;         // ❌ i 和 t 在这里都已失效
}
```

> 💡 **作用域 ≠ 存储位置**。第 2 节讲的是"变量存在内存哪个区、活多久"，
> 这一节讲的是"代码里哪些地方能写这个名字"。`static` 局部变量就是典型例子：
> 它**存在静态区**（活到程序结束），但**作用域仍只在函数内**。

### ⚠️ `for (int i = ...)` 里的 `i` 出了循环就没了 🔴

循环结束后还要用它，就得定义在循环外面：

```cpp
int i;
for (i = 0; i < n; i++) {
    if (a[i] == target) break;
}
cout << i;    // ✅ 现在能用了（知道找到的位置）
```

> 🔴 第二轮实战中真会遇到（查找后要知道停在哪）。
> 🟡 第一轮也常考"下面程序能否编译通过"。

### 变量遮蔽（同名覆盖）🟡

内层同名变量会**盖住**外层的：

```cpp
int x = 100;              // 全局

int main() {
    int x = 5;            // 局部 x 盖住全局 x
    cout << x;            // 5
    {
        int x = 9;
        cout << x;        // 9
    }
    cout << x;            // 5   ← 出块后又是局部那个
}
```

实测输出：`5 9 5`

> 🟡 **第一轮"阅读程序写输出"的经典陷阱**，要能一眼看出每个 `x` 指的是谁。
> 🔴 但第二轮**自己写代码时要坚决避免同名**——遮蔽造成的 bug 极难发现。

## 6. 全局变量 vs 局部变量 🔴

这是第 2 节那张表里**最该吃透的两行**：

| | 全局变量 | 局部变量 |
|---|---|---|
| 定义位置 | 所有函数外面 | 函数或 `{}` 内 |
| 默认值 | **自动为 0** 🔴 | **随机垃圾值** 🔴 |
| 存放区域 | 静态区（很大） | 栈（通常仅 1~8 MB） |
| 生存期 | 程序全程 | 出了 `{}` 就销毁 |
| 可见范围 | 整个文件 | 所属 `{}` 内 |

实测：全局的 `int`、`bool`、`double`、数组、结构体成员，未赋值时**全是 0**。

> 🔴 **"全局默认 0、局部是垃圾"这一条两轮都考**，是本文最该记住的对比。

### ⚠️ 高频丢分点：大数组必须开成全局 🔴🔴

```cpp
int main() {
    int arr[3000000];     // ❌ 12 MB 放栈上 → 程序直接崩溃
}
```

实测：上面这段**运行即崩**（无任何输出，异常退出）；挪到全局则正常运行。

```cpp
int arr[3000000];         // ✅ 放静态区，没问题

int main() {
    ...
}
```

**经验法则：数组大小超过几万，就定义在全局。** 顺带白送一个"自动清零"。

> 🔴 **第二轮血泪教训**：本地小样例能过，交上去大数据直接 RE（运行错误），
> 报错信息什么都看不出来，查半天查不到。**养成习惯：数组一律写在 `main` 外面。**

### 全局数组的清零 🔴

```cpp
#include <cstring>

int a[100005];
memset(a, 0, sizeof(a));       // 整个数组置 0
memset(a, 0x3f, sizeof(a));    // 置成约 1e9，用作 INF（最短路/DP 初始化）
```

⚠️ `memset` 是**按字节**填充，所以只有填 `0`、`-1`、`0x3f` 才符合直觉。
`memset(a, 1, ...)` **不会**把数组填成 1（实测得到 `16843009`）。

> 🔴 **多组数据的题**（"本题有 T 组测试数据"）每组开始前必须清空全局变量/数组，
> 否则上一组数据残留 —— 第二轮又一个高频 0 分点。

## 7. 常量 `const` 🟡

加上 `const` 表示"定义后不许改"，改了直接编译报错。

```cpp
const int MAXN = 100005;
int a[MAXN];                     // ✅ 常量可以用来开数组
MAXN = 200;                      // ❌ 编译错误
```

`const` 本身不是考点，但下面这**两个用法第二轮极常用**：

```cpp
const int INF = 0x3f3f3f3f;      // 🔴 求最小值的初值、最短路的"不可达"
const int MOD = 1000000007;      // 🔴 题目要求"答案对 10^9+7 取模"时

ans = (ans + x) % MOD;
```

> 🔴 **`0x3f3f3f3f` 为什么好用**：它足够大（约 10.6 亿），而且**两个相加仍不溢出 int**
> （实测 `0x3f3f3f3f + 0x3f3f3f3f = 2122219134` < `INT_MAX`），最短路松弛时不会炸。
> 而且它正好能配合 `memset(a, 0x3f, sizeof(a))` 批量初始化。

### `constexpr` ⚪

C++11 起的"编译期常量"，在 CSP 范围内和 `const` 效果基本一样：

```cpp
constexpr int C = 100;
int arr[C];                      // ✅ 能用来开数组（实测通过）
```

> ⚪ **考场上写 `const` 就够了**，两者在 CSP 用得到的场景里没有区别。
> 列在这里只是因为第 2 节的分类表提到了它，读别人代码时不至于陌生。

## 8. `auto` 自动类型推导 🟡（仅 CSP-S 需要）

> **CSP-J 可以跳过这一节** —— J 组基本不碰 STL 容器，用不到 `auto`。

让编译器自己看右边是什么类型：

```cpp
auto i = 42;              // int
```

单独这么用没意义。真正的价值是**遍历 STL 容器**时省下一长串类型名：

```cpp
map<string, int> mp;

for (auto it = mp.begin(); it != mp.end(); it++) { ... }     // 迭代器
for (auto& p : mp) cout << p.first << " " << p.second;       // 范围 for
```

⚠️ `auto` 不能防溢出：`auto x = 1000000000 * 3;` 推出来仍是 `int`，照样溢出。

## 9. 类型转换 🔴🔴（全文最重要一节）

### 整数除法会丢小数 🔴

```cpp
cout << 7 / 2;         // 3      ← 两个整数相除，小数部分直接丢弃
cout << 7 / 2.0;       // 3.5    ← 有一个是小数，就按小数算
cout << (double)7 / 2; // 3.5
```

```cpp
double d = 3.99;
int t = d;             // t = 3   ← 截断，不是四舍五入！
```

要四舍五入得自己写 `(int)(d + 0.5)` 或用 `round()`。

> 🔴 第一轮考"输出是什么"；第二轮算平均值、比例时忘了转 `double` 就答案错误。

### ⚠️ 高频丢分点：`int` 相乘溢出 🔴🔴🔴

```cpp
int a = 100000, b = 100000;

int c = a * b;                  // ❌ 1410065408（错的）
long long d = a * b;            // ❌ 1410065408 ← 仍然错！
long long e = (long long)a * b; // ✅ 10000000000
long long f = 1ll * a * b;      // ✅ 10000000000（更简短，竞赛常用）
```

上面四行是实测结果。**第二行是最阴险的坑**：虽然结果变量是 `long long`，但 `a * b` 这个乘法**先按 int 算完**再赋值，错误早就发生了。

**必须在参与运算之前就把类型提上去。**

### 极限值 🔴

| 常量 | 值 |
|---|---|
| `INT_MAX` | 2147483647（约 2.1×10⁹） |
| `INT_MIN` | -2147483648 |
| `LLONG_MAX` | 9223372036854775807（约 9.2×10¹⁸） |

```cpp
cout << INT_MAX + 1;   // -2147483648  ← 溢出后绕回负数
```

> 🔴🔴 **这是 CSP 第二轮第一大失分点，没有之一。**
> 出题人会**故意**把数据范围设成 $10^9$，就等着你用 `int` 丢分
> （[P5681 面积](../P5681/question.md) 就是典型，用 `int` 只有 80 分）。
>
> 💡 **口诀**：读完题先看数据范围，估算结果量级，
> **只要可能超过 2×10⁹ 就用 `long long`。拿不准就直接上**，没有任何实质代价。

## 10. 变量的常用操作

### 交换两个变量 🔴

```cpp
swap(a, b);                    // ✅ 直接用标准库
int t = a; a = b; b = t;       // 🟡 手写版，第一轮可能考
```

### 多变量输入输出 🔴

```cpp
int a, b, c;
cin >> a >> b >> c;              // 读三个数
cout << a << " " << b << endl;   // 注意自己加空格
```

### 复合赋值与自增 🔴 / 🟡

```cpp
a += 5;        // 🔴 等价 a = a + 5，同理 -= *= /= %=
a++;  ++a;     // 🔴 都是 a 加 1，单独成句时两者完全一样

int b = a++;   // 🟡 先把 a 的旧值给 b，a 再加 1
int c = ++a;   // 🟡 a 先加 1，再把新值给 c
```

实测：`int p=5; int q=p++; int r=++p;` → `q=5, r=7, p=7`。

> 🟡 **第一轮"阅读程序写输出"必考套路**，会把一串 `i++`、`++i` 混在表达式里让你算。
> 🔴 但**第二轮自己写代码时只在单独成句时用**（`i++;`）。
> 永远不要写 `a = a++ + ++a;` 这种代码——绕晕自己，行为还可能是未定义的。

## 11. 检查清单 🔴（第二轮交题前必看）

- [ ] 🔴 结果可能超过 2×10⁹ 吗？超了就换 `long long`
- [ ] 🔴 两个 `int` 相乘的地方，加 `1ll *` 了吗？
- [ ] 🔴 所有局部变量都初始化了吗？（尤其 `sum`、`cnt`、`ans`）
- [ ] 🔴 大数组（>几万）定义在全局了吗？
- [ ] 🔴 数组开够大了吗？（按 $n$ 的上限 +5）
- [ ] 🔴 多组数据的题，每组开始前清空了全局变量/数组吗？
- [ ] 🔴 算平均值/比例时转 `double` 了吗？
- [ ] 🟡 变量名有没有和 `max`、`min`、`count`、`y1` 撞车？
- [ ] 🟡 判断相等用的是 `==` 而不是 `=` 吗？

## 12. 按考试阶段的复习路线

### CSP-J（入门级）

| 轮次 | 看哪几节 |
|---|---|
| **第一轮**（笔试） | 2 分类表前三行、4 命名规则、5 作用域+遮蔽、9 整数除法、10 `++i`/`i++` |
| **第二轮**（编程） | 3 初始化、6 全局局部+大数组、9 溢出、11 清单 |

**可跳过**：第 8 节 `auto`、第 2 节的成员变量/`register`、第 7 节 `constexpr`。

### CSP-S（提高级）

在 J 组基础上加：

- **2 成员变量（结构体）** 🟡 —— 图论存边、自定义排序的基础
- **8 `auto`** 🟡 —— 大量使用 STL 容器时必备
- **7 `const INF / MOD`** 🔴 —— 图论、DP、取模题天天用
- **6 `memset(a, 0x3f, ...)`** 🔴 —— 最短路、DP 初始化的标准操作

## 总结口诀
